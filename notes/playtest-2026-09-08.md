# Playtest notes — 2026-09-08

Running notes from the first Riftbound game between the desktop kai and a
headless `kai-cli` seat. Each item is a thing to build or fix, written down as
it came up at the table. The second pass (later the same day) built the list;
what each item became is noted under it as **built:**.

- **Per-player playmats.** Today the playmat is a local render choice that
  paints every mat on your own screen. Each player should pick their own mat
  and everyone should see it: carry the choice on the roster (a `SeatInfo`
  field like the seat colour, or a spirit-stored blob hash the other peers
  fetch), and let a headless seat set it too.
  **built:** `SeatInfo.playmat` on the roster, `ClientMsg::PickPlaymat`; the desktop sends its choice whenever the tuning changes, `kai-cli --playmat` / `playmat <link|card:name>`, every client fetches the other seats' mats and paints each seat with its own.
- **Default peers seeded by node id go stale.** dev1 and dev2 changed node
  ids with spirit's device-key work, so every client seeding the baked ids
  sat alone in the mesh and saw no tables. Seed the gateways by something
  that survives a key change — their device-group id or the `/gateway/status`
  node id fetched at launch — instead of a constant.
  **built:** spirit's `Mesh::seed` accepts a gateway URL and resolves `/gateway/status` (`ticket`, then `node_id`); kai seeds each default peer by URL first and falls back to the baked id.
- **The store lock outlives a dead process.** spirit's new `lock` file records
  a pid and refuses the store while the file exists, even after that pid is
  gone, so every restart of kai after a crash or kill needs `rm
  ~/.spirit/store/lock` by hand. The lock should check the pid is alive (or
  use an OS advisory lock) before refusing.
  **built:** the lock checks the recorded pid is alive (`/proc` on Linux) and takes over a dead one.
- **Table adverts travel one hop.** A gossip view carries only the sender's
  own table, so a seat sees a host's table only once it gossips with the host
  directly; the gateways introduce the host's address but do not relay the
  advert. Either relay learned tables through the gateways or have hosts
  register tables with them.
  **built:** gossip views carry `heard_tables`; a node relays the adverts it heard (deduped, expiring, never its own) so a seat sees a host's table through the gateways.
- **A Piltover Archive import lost its legend on the second fetch** (31
  faces then 30 with one unresolved) — the resolver is not deterministic
  across runs; log which identifier failed and retry it.
  **built:** the store catalogue's prefix lookup met the signature printing (`unl-230*`) before the base card and stopped; fixed, plus retries with backoff and an `unresolved` report naming the identifier and reason.
- **Dealing twice is silent.** The joiner's second `DealDeck` is refused by
  the host as already dealt, but nothing comes back to the seat that sent it.
  **built:** the host answers `HostMsg::Notice` and the seat prints it.
- **Token spawn menu.** A way to put a token onto the table — pick from the
  tokens the plugin declares (or the ones a card makes), choose a zone, and it
  appears as a card with a generated face. The engine already has the shape
  in the plugin design (`SpawnCard { face, zone, seat }` as an effect); the
  client needs a menu and the plugin a token list in its manifest.
  **built:** `K` opens the token window (the plugin's manifest tokens plus a custom name and might, onto any base or battlefield), `LogAction::Spawn`, `kai-cli spawn <token> <zone> [might]`.
- **`kai-cli draw` defaulted to the first deck-kind zone**, which is the rune
  deck in Riftbound's table, so a bare `draw` channelled a rune into the hand.
  It prefers `main` now (fixed in source, takes effect on the next restart).
- **No energy or rune payment.** Playing a card is a free move; runes are
  exhausted by hand if at all. The plugin could count exhausted runes as
  energy for the turn and the client could show a card's cost next to it.
  **built:** faces carry energy and power; the plugin exhausts ready runes for energy and recycles for power when a card leaves the hand for the base, a battlefield or the chain, and refuses a play it cannot pay.
- **Tokens, again, from the table.** Lillia's sprite token attacked an empty
  battlefield with nothing to show for it; the showdown ran on trust. The
  token spawn menu above is the first thing the next session should build.
- **Points are not visible at the table.** The seat counters (points, XP)
  exist as declared counters but there is no plate on screen and no way to
  score a conquer or a hold from the strip. Show each seat's points beside
  its name and let a showdown's resolution offer "conquer" to the winner.
  **built:** the plugin strip prints every seat's points, who holds each battlefield and the winner at eight; conquer and hold are scored by the plugin.
- **Auto-draw at the draw phase**, and by the same token auto-channel two
  runes and ready everything at awaken: the plugin knows the phase and the
  zones, so "end beginning phase" should do the start-of-turn choreography
  itself (the fold needs plugin effects for that — Move and Annotate as
  verdict effects, which the design already names).
  **built:** end beginning phase awakens, scores holds, channels and draws through verdict effects.
- **Auto-channel at the channel phase** (two runes from the rune deck to the
  pool, three on the second player's first turn — the seat that went second
  starts a rune up), alongside the auto-draw above.
  **built:** two runes, three on the last seat's first turn.
- **Costs are invisible.** The headless seat played Noxus Hopeful (4 energy)
  with two runes and Dunebreaker (7 energy, 1 power) with four; the table let
  it. The catalogue knows every cost — show it on the card and let the plugin
  count ready runes as the energy available this turn.
  **built:** the hover preview captions kind, energy, power and might; kai-cli prints them beside each card.
- **Auto-awaken and hold scoring.** At the beginning phase the plugin should
  ready everything the turn player controls and, for each battlefield they
  hold a unit on, score a hold point on the points counter — both are pure
  reads of the table plus effects, once verdicts can carry them.
  **built:** see above; control is settled from who has units on a battlefield.
- **Playing cards face down.** A card moved into a public zone reveals its
  face by design; there is no way to play something hidden (a face-down
  unit, an ambush) and reveal it later. Add a "play hidden" move that keeps
  the face on the owner's channel until an explicit reveal.
  **built:** `H` plays the hovered hand card face down onto the base (`WireIntent::MoveHidden`, no reveal), `R` reveals it later; kai-cli `hide`/`reveal`.
- **A revealed card stayed readable after returning to hand.** Dunebreaker
  was revealed on the base, moved back to hand, and the opponent's client
  still painted its face on the hand card (upside down, being a foreign
  hand). The view builder let a past reveal override an owner-only zone;
  fixed so a reveal only counts while the card sits in a public zone.
  **built:** fixed in the view builder.

- **A recycled rune arrived in the deck sideways.** Exhaust is an annotation
  and nothing cleared it when the card left play.
  **built:** the engine sheds annotations and card counters when a card enters
  a hand, deck or discard zone.
- **Right-click** already recycles a rune or trashes any other card
  (`zones::recycle_move`); it stays, and the token window and hidden plays
  got hotkeys beside it (`K`, `H`, `R`).
- **Battlefield pictures vanished from the chooser.** The playmat section and
  the battlefield prompt each registered the same image with egui and each
  removed it when it closed, so whichever closed first blanked the other.
  **built:** one `EguiArt` registry hands out texture ids and never removes
  them.
- **Rewind.** A way to undo the last action from the table: Shift+Backspace
  takes back the most recent entry (yours, or the last one on the log with the
  host's say), so a misclick or a rule the plugin applied wrongly does not
  need the counters menu to repair. The log is append-only, so this is a
  compensating entry (a `Rewind { to: seq }` action every replica folds by
  refolding the log to that point) rather than a deletion.

## Second game (new build)

- **The play was free.** The host appended a hand play as move then reveal, so
  the decider judged the move before it could see the card's cost.
  **built:** the host decides the move on a preview with the face revealed,
  then appends reveal and move; a card leaving a face-down deck still moves
  first, since the engine refuses a reveal inside a hidden zone.
- **A drawn card came through as `?`.** Draws made by plugin effects skipped
  the private face channel, which only watched Move actions.
  **built:** `owed_faces` sends a seat every face it is owed for unrevealed
  cards in its owner-visible zones after each entry.
- **Channelled runes stayed face down.** Effects that move a card into a
  public zone appended no reveal.
  **built:** the host reveals whatever an entry surfaced into a public zone.
- **Old decks had no kinds.** A deck recalled from history predates card
  kinds, so its battlefield terrain counted as a unit and "held" its zone.
  **built:** history restore backfills kind, energy, power and might from the
  store catalogue.
- **Units are played to the base**, not onto a battlefield; an attack is a
  move from the base. A played unit enters exhausted (barring Accelerate), a
  move needs a ready unit and exhausts it.
  **built:** the plugin refuses a unit play onto a battlefield and a march by
  an exhausted unit, exhausts a played unit and a marching one.
- **Per-seat playmats work** across the table; switching mid-game repaints
  the other seat.
- **Tapping a rune should give energy.** The plugin pays a play by exhausting
  ready runes itself, so a ready rune is one energy and tapping is how it is
  spent; power comes from recycling a rune of the card's domain. What is
  missing is floating energy: a rune tapped by hand (for an ability, or
  ahead of a play) should count toward the next cost this turn instead of
  being lost. Track a per-seat energy pool in the plugin state that manual
  exhausts feed and plays drain, emptied at the end of the draw phase.
- **Tokens showed as backs.** A spawned face lived only in the fold; clients
  and the host learned faces from Reveal entries and deals, so a token's face
  never reached anyone's face map, and its art was fetched by fuzzy name
  ("Sprite" found Sprite Mother).
  **built:** sessions harvest every non-hidden face out of the folded state,
  token art is fetched by the manifest's card id, and Gold (gear, `sfd-t03`)
  joins the token list.
- **Tokens should vanish** when they reach the trash or a hand.
  **built:** the engine remembers which cards were spawned and removes one
  the moment it enters a hand, deck or discard zone.
- **Might should read as a total.** A unit's badge showed only the counter,
  so a 3-might Vi with +2 read "might 2".
  **built:** the might badge shows base might plus the counter, and every
  unit with a printed might wears one; the popup still nudges the bonus.
- **Sprites are temporary.** A Sprite token spawned bare and stayed.
  **built:** the plugin marks a spawned Sprite temporary and kills every
  temporary card of the turn player at the start of their beginning phase,
  before scoring; tokens vanish in the trash.
- **Nobody said who won.** Eight points ended nothing.
  **built:** the plugin reports a winner on its view, kai shows a "player x
  won" dialog with leave table (to the games menu), new game (the host
  resets and everyone deals in; a guest asks the host) and select deck (the
  lobby). The final point follows 448.1.b: at seven, a hold scores it, a
  conquer scores it only when every battlefield was scored this turn, and
  otherwise the conqueror draws a card instead.
- **A hidden play was revealed by the host.** The pass that reveals cards
  surfaced by effects also revealed a card played face down.
  **built:** the host remembers hidden plays and leaves them out of that
  pass until the owner reveals or moves them.
- **Spectators and a start gate.** Today anyone who joins takes a seat and
  a game begins with whoever is there. Wanted: a lobby phase where players
  join before "start game", a spectator role for anyone who joins after the
  start (or chooses to watch), and a spectate entry on the tables list for
  games in progress. On the wire this is a seat kind on the roster
  (player/spectator) that the host assigns from the game state, a
  `StartGame` gate that closes seating, and the view builder sending
  spectators the public table with no private faces.
- **An AI opponent.** `kai-cli --ai` seats a language model (NanoGPT, GLM
  5.3 Flash by default) that gets the whole table, every visible card's text
  and cost, its own notes and the numbered actions, and acts through tools
  each time the strip offers it an action — a turn, focus in a showdown, a
  roll. Follow-ups: a desktop button that spawns the AI seat against your
  table; an Ollama backend; letting the model see the log of the last few
  entries so it can read what the opponent just did.
  **built:** the Riftbound lobby's "AI opponent" section launches the seat
  against your table (model, deck or "let the AI pick"), `B` opens a chat
  window whose messages reach the seat's prompt and a model switcher that
  the seat picks up on its next decision; before the game the seat loads a
  deck by saved label or link, picks a battlefield and deals. Default model
  is DeepSeek V4 Flash (fast); GLM 5.3 Flash thinks longer and slower.
