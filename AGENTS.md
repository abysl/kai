# kai — Agent Rules

The Bevy 3D card table. Read [`wiki/design/table.md`](wiki/design/table.md)
before touching the renderer, and agni's
[`architecture.md`](../agni/wiki/design/architecture.md) for the
simulation boundary it renders.

## The rule that matters

Nothing in this app may mutate game state. Dropping a card emits `CardDropped`
— a request. `net::route_drops` routes it on every target: solo applies
directly (the accept-everything stand-in a rules engine will replace), a
session host applies it through `agni_net::session::HostSession::intent` — the
validation point a rules engine plugs into — and a session client only
forwards it to the host. Easing, hover,
camera framing and frame timing are free to be non-deterministic; agni-core
and agni-sim are not, and their rules are enforced over there.

The deterministic log, the sessions, and the transport all live in agni now
(`agni-sim`, `agni-net`) — kai renders, panels, and routes. If a change here
wants to touch fold, session, or wire code, it belongs in
`../agni/`, under agni's `AGENTS.md`.

## Versioning

kai carries a `major.minor.patch` version in `Cargo.toml` and **every push that
ships a build bumps it**. `settings::build_line` renders
`v<version> · wire <WIRE_VERSION>` from `env!("CARGO_PKG_VERSION")` and
`agni_net::session::WIRE_VERSION` in the settings header (U5 moves it to the
advanced tab), so the running build identifies itself in one click.

- **patch** — fixes, tuning and small visible tweaks: a layout tightened, a
  default changed, a knob removed. Most pushes are patches.
- **minor** — a bigger non-breaking feature release: a new screen, a new flow
  a player learns, something the release notes would lead with.
- **major** — reserved for a break we choose to call one.

The wire version is separate and moves only when the session protocol changes.
When it does, **every peer must be on the same build**: the host refuses a
mismatched joiner with "wire protocol N does not match this build's M". The web
peer is deployed by `.woodpecker/agni-artifacts.yml`, which runs **only on a
push to main**, so a wire bump that sits on a branch breaks web↔desktop play
until it lands. **Web and desktop deploy together**: bump the wire version,
regenerate `agni/net/tests/fixtures/{client,host}_v<N>.hex` with
`AGNI_GOLDEN_WRITE=1`, and land it all on main in one push, or expect joins
to fail in between. A joiner that lacks the modules the host pinned no longer
needs the gateway to hold them — the host serves its own engine and plugin
over the table link (`NeedModule`/`Module`, `wiki/design/multiplayer.md`
"Pinned modules") — so the wire version is the only thing a dev-built host
and a deployed browser must still agree on.

## Dev Environment

devenv provides the toolchain; there is no system-wide cargo.

```
direnv allow          # or: devenv shell
dev                   # run the table, dynamically linked (fast iteration)
run                   # run it the way CI builds it
build | unit-test | clippy | fmt | fmt-check
web-build | web-serve # wasm bundle into web/dist, serve on :8123
web-clippy            # clippy for wasm32 (getrandom wasm_js cfg applied)
```

- The test script is `unit-test`, never `test` — bash resolves `test` to its
  builtin, so a script by that name is unreachable.
- `fmt` and `fmt-check` format the WHOLE monorepo, from the root `treefmt.toml`.
- `dev` enables `bevy/dynamic_linking`. Never ship a build with it: it requires
  distributing `libbevy_dylib` alongside the binary.
- `.cargo/config.toml` selects clang + mold on Linux. Both come from devenv; a
  shell without them will fail to link.
- `web-build` needs the exact wasm-bindgen CLI matching Cargo.lock, cargo-installed
  into `.wasm-tools/` (nixpkgs lags). See `wiki/design/table.md` for the runbook.
- The android toolchain lives in `android/`'s OWN devenv (SDK/NDK/gradle are
  heavy and unfree); build the APK with `android-build` from that shell, never
  from this one. `android-release` is the publishable variant — signed from
  `KAI_KEYSTORE_*` in the environment, versioned from git; see the README's
  Versioning and Auto-updates sections before touching either.
  Android-only code sits behind `#[cfg(target_os = "android")]`
  and must keep desktop and wasm builds untouched — bevy's
  `android-game-activity` feature is required (0.19 defaults omit it) and pairs
  with the games-activity 4.4.0 AAR in `android/app/build.gradle`; bump those
  two together or the app crashes at launch.

Measured on jet (96 cores), Bevy 0.19:

| | Time |
|---|---|
| cold build | ~4m |
| incremental, `dev` (dynamic linking) | **1.8s** |
| incremental, `run` (static) | 5.7s |

The 3x gap is why `dev` exists. Switching between `dev` and `run` relinks
everything once, so pick one and stay in it while iterating.

## Traps

- The p2p modules do NOT share one cfg gate. `sync.rs` is android-only;
  `node.rs`, `identity.rs`, `peers.rs` and `net.rs` compile on every target
  with per-item gates — hosting paths are `not(wasm32)`, joining works
  everywhere. Copying the wrong gate onto a new module either breaks the wasm
  build or silently drops the module from android; check all three targets.
- Clipboard is not free anywhere but desktop. bevy_egui compiles its whole
  `EguiClipboard` out on android, and on wasm winit calls `preventDefault()`
  on every canvas keydown, which cancels the browser's default paste and so
  the `paste` event bevy_egui listens for never fires. Route every copy and
  paste through `src/os/clipboard.rs`, and give each one a visible button — a
  keyboard shortcut is not reachable on a phone.
- Typed text is not free on android either. winit 0.30's android backend drops
  `InputEvent::TextEvent` in a catch-all arm and never emits
  `WindowEvent::Ime`, so bevy_winit's and bevy_egui's complete, default-on IME
  path never receives anything and every soft-keyboard keystroke is lost —
  while the keyboard itself appears, because `set_ime_allowed` DOES map to
  `AndroidApp::show_soft_input`. Text comes in through `src/os/ime.rs` instead.
  Do not "fix" this by enabling something in bevy_egui; there is nothing to
  enable, and do not disable its IME systems either — they are what shows and
  hides the keyboard.
- A debug panel reachable only by a keypress is unreachable on android. Give
  anything you add an on-screen toggle; a key can be the desktop shortcut, not
  the only way in.
- Do not show a peer as offline because we are not connected to it. iroh 1.1
  has no liveness probe and no way to enumerate remotes, so "not connected" and
  "down" are indistinguishable. `wiki/design/peers.md` records what the API can
  and cannot support before you add a status dot.

## Runtime knobs

`AGNI_HAND=all|n` sizes the free-form sample hand, `AGNI_PLAYERS=n` seat
count, `AGNI_TUNING=path` tuning file override. Card art comes from the user's
spirit store, then an on-the-fly Riftcodex/Scryfall fetch (native+android), or
the gateway bridge (wasm); no art in reach plays a named placeholder.
